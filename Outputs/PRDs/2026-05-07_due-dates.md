# PRD: Due Dates

> **Backlog item:** TASKLEY-012 — Add due dates to tasks
> **Status:** Shipped in v1.0

---

## TL;DR (GIFTS)

- **Goal:** Help users know which tasks need attention today vs. what can wait, by letting them set a date on any task and surfacing overdue items clearly.
- **Insights:** Users were using priorities as a time proxy ("mark P1 today, change it tomorrow"). Due dates were the #1 post-v0.9 request. Without a time dimension, everything in the list feels equally urgent.
- **Focus:** Date assignment per task, overdue visual treatment, clearing a date. Not recurring tasks, reminders, or calendar sync.
- **Trade-offs:** Date-only (no time) vs. full datetime - chose date-only to reduce friction and avoid timezone complexity in the MVP.
- **Suggested solution:** Calendar popover per task; overdue tasks get a destructive red accent; clear date option inside the picker.
- **Success:** 40%+ of active tasks have a due date within 30 days of launch; overdue completion rate rises after feature ships.
- **Release shape:** Full feature in v1.0 alongside Notes. No feature flag needed.

---

## Context

- **Background:** Taskley v0.9 launched with task creation, priorities, and checkboxes only. No time dimension - every task sat in a flat list with no signal about urgency vs. scheduling.
- **Why now:** v0.9 feedback showed users were hacking priorities to encode time. Due dates are the clearest gap between Taskley and alternatives like Todoist and Things. Users are evaluating whether to stay.
- **Constraints / assumptions:**
  - Single-user app; no shared calendar or team scheduling in scope
  - No push notification infrastructure; overdue detection is visual-only for now
  - Supabase schema requires a new nullable `due_at` column
  - localStorage fallback must also carry `due_at`

---

## Goals

- Let users assign a date to any task with minimal friction (2 taps on mobile, 1 click on desktop)
- Surface overdue tasks visually so nothing falls through unnoticed
- Allow clearing a date when it's no longer relevant

## Non-goals

- Recurring tasks
- Push or email reminders
- Time-of-day precision (date-only for MVP)
- Google Calendar sync
- Bulk date assignment

---

## Users & primary use cases

- **Primary user:** Sarah (PhD student) - tracks coursework deadlines and research milestones alongside daily life tasks
- **Primary scenario:** Sarah has a lit review due Friday. She sets the due date Monday. By Thursday the task signals urgency visually. She checks it off before midnight.
- **Secondary scenarios:**
  - David sets a due date on "Follow up with Noa about PR" after a 1:1, so it surfaces before their next sync
  - Maya assigns a due date to a client deliverable and can see at a glance which deadline is closest

---

## Requirements

### Functional requirements

- [FR1] Any task can have an optional due date (date-only; no time of day required from user)
- [FR2] Due date is stored as end-of-local-day ISO timestamp (`23:59:59.999`) to avoid timezone edge cases around "due today"
- [FR3] A task with no due date shows "Set due" as a muted prompt; a task with a date shows the formatted date (e.g. "May 7")
- [FR4] A task is overdue if: `due_at` is set, task is not complete, and current time > `due_at`
- [FR5] Overdue tasks render with a destructive red left border, red due date text, and an "(overdue)" label inline
- [FR6] The date picker opens in a popover anchored to the due date button
- [FR7] A "Clear date" button inside the popover removes the due date
- [FR8] Due date persists in both localStorage (local mode) and Supabase (cloud mode)

### UX / UI notes

- **Trigger:** Pill-shaped button per task, same action row as the priority selector
- **States:**
  - No date: "Set due", muted/ghost style
  - Date set: formatted short date, normal style
  - Overdue: formatted date, destructive red, "(overdue)" appended
- **Picker:** shadcn `Calendar` in single-select mode; "Clear date" button below calendar grid
- **Empty / error:** if save fails, toast error; date reverts to previous value
- **Mobile:** popover anchors `align="end"` to avoid overflow; pill button goes full-width below `sm` breakpoint

### Data & analytics

- Events to track:
  - `due_date_set` - properties: `task_id`, `days_from_now` (buckets: same-day, 1-3d, 4-7d, 8-30d, 30d+)
  - `due_date_cleared` - properties: `task_id`, `was_overdue`
  - `overdue_task_completed` - properties: `task_id`, `days_overdue`
- Key KPIs:
  - % of active tasks with a due date set (target: 40% within 30 days of launch)
  - Overdue completion rate: overdue tasks completed same day vs. left overdue

#### Success (quality check)

- **Unit of value:** % of tasks with a due date - reflects actual use, not just feature discovery
- **Truth detector:** if overdue completion rate rises, users are acting on the signal, not ignoring the red
- **Actionable:** team can reduce picker friction to lift adoption if target isn't hit

### Performance & reliability

- Date picker popover must open in < 100ms
- Due date updates applied optimistically - no loading state visible to user
- Overdue check is client-side on render; no polling or server-side job for MVP

### Edge cases

- Task completed while overdue: remove overdue styling immediately on check
- User timezone differs from server: storing as local-day end minimizes "wrong day" bugs; accepted risk for v1
- No due date set: `due_at` is `null`; no overdue check runs
- Date cleared on an overdue task: remove overdue styling immediately

---

## Acceptance criteria (definition of done)

- [ ] Any task can have a due date assigned via calendar popover
- [ ] Tasks with no due date show "Set due" prompt in muted style
- [ ] Tasks with a due date show formatted short date (e.g. "May 7")
- [ ] Overdue tasks render with destructive red styling and "(overdue)" label
- [ ] Completing an overdue task removes overdue styling immediately
- [ ] Clear date removes the due date and reverts task to no-date state
- [ ] Due dates persist in localStorage (local mode) and Supabase (cloud mode)
- [ ] Date picker is usable on mobile without input obscuration or overflow

---

## Rollout plan

- Ship in v1.0 alongside Notes field (both require Supabase schema migration)
- Migration: add `due_at TIMESTAMPTZ` column, nullable, default `null`
- No feature flag needed - purely additive, no breaking change
- Backward compatibility: existing tasks get `due_at: null` automatically; no data migration needed

---

## Risks & mitigations

- **Timezone confusion:** Storing as end-of-local-day ISO reduces "task shows overdue a day early" reports; accepted risk for v1
- **Overdue anxiety:** Users with many overdue tasks may feel stressed by the red. Mitigated by keeping the styling prominent but not alarming (border + text, not full background)
- **Mobile picker UX:** Popover may overlap content on small screens. Mitigated by `align="end"` and full-width layout under `sm` breakpoint
